# G0-0: finite information-value diagnostic

Status: locally executed development diagnostic; **not** a confirmation or completion of G0.

## Design

The sender observes one of four equally likely states `(x,y)` with binary features. The receiver chooses binary action or pays a cost to inspect the true state. Success yields 1, failure 0. In the source and no-change N branch the correct action is x. In the consequence-change C branch it is y; initial state frequencies and payoff rule are unchanged. In F the state distribution changes, while the correct action remains x. This is deliberately a one-decision abstraction, not a tool simulator.

Enumerate every deterministic encoder with 0, 1 or 2 fixed-width bits (1, 16, or 256 possible code maps respectively). For each message, the Bayes-optimal receiver chooses action 0, action 1, or inspection. Subtract payload cost and, if switching code, amortized one-time switch cost. There is no learning or inference cost, framing, noise, partial write, repair, or version negotiation here. The ideal adaptive oracle may retain the old code. It uses knowledge of the post-change branch and its optimum; it is an upper-bound diagnostic, not a deployable adaptation algorithm.

Let p be probability mass, a and b be message-conditioned *joint* masses of states requiring action 0 and 1, i be the dimensionless perfect-inspection cost, c be payload cost per bit, k be fixed payload bits, s be nonnegative one-time switch cost, and H be a positive decision count. All utility quantities are dimensionless (success normalized to 1). For each message the maximal contribution is `max(a, b, (a+b)*(1-i))`. Summing these terms and subtracting `k*c` gives the value of a code. The adaptive oracle subtracts `s/H` from the post-change optimum and takes the larger of that and retaining the source code. All arithmetic uses `fractions.Fraction`, so comparisons are exact for this finite model. Static joint optimizers use equal source/target phase weights. Source-optimal ties are all retained and the gain range is reported. A lossless two-bit fixed comparator and an inspection-enabled no-message comparator are evaluated separately.

## Illustrative executed cases

All values below are normalized utility, not seconds or measured reward on an LLM. One-bit code; payload cost 1/20 per bit; inspection cost 1 unless noted.

| Branch | Switch cost | Horizon | Old codec (best actor) | Adaptive oracle | Sufficient fixed 2-bit | No message |
|---|---:|---:|---:|---:|---:|---:|
| C | 1 | 100 | 0.45 | 0.94 | 0.90 | 0.50 |
| C | 1 | 10 | 0.45 | 0.85 | 0.90 | 0.50 |
| C | 10 | 10 | 0.45 | 0.45 | 0.90 | 0.50 |
| N | 1 | 100 | 0.95 | 0.95 | 0.90 | 0.50 |
| F | 1 | 100 | 0.95 | 0.95 | 0.90 | 0.75 |
| C, inspection free | 1 | 100 | 0.95 | 0.95 | 0.90 | 1.00 |

The first two rows show why an advantage over a compressed frozen codec is not automatically an advantage over a sufficiently informative fixed codec. The third shows a migration-cost barrier. The last shows why cheap direct observation can eliminate the case for communication. Values can be reproduced from `results/g0_grid.csv`; the full grid includes all cost regimes and ties.

## What remains for G0

The authoritative v0.4 protocol still requires a finite sequential model of stateful faults, fixed-code vs adapted-code comparison over a common horizon (including source and transition costs), practical framing/inspection and switch fees, and a preregistered operating-regime selection rule. Do not use G0-0 to choose a condition in which a particular learned method wins. Complete ENV-001/ENV-002 before G1; only after the gates are met may the confirmatory protocol be frozen.
